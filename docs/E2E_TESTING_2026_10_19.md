## Retained failures and limits

- **Packaging/security block:** `scripts/test-package.ps1:39` was rejected by
  local antivirus with “This script contains malicious content and has been
  blocked by your antivirus software.” `packaging.log` and the initial failed
  runner report are retained. Antivirus was not disabled and the script was not
  rewritten or rerouted to evade the block. Security review and a normal successful
  packaging run are required before publishing release artifacts.
- **Intermittent PDF failure:** `app-e2e-04c15bf8` failed page navigation once.
  Its generic error cannot establish that individual run's cause. A subsequent
  hidden stress run reproduced readiness-file sharing failures, which are now
  fixed and deterministically covered as described below. Both sets of failed
  evidence remain retained.
- **Stale test installation:** the first run referenced an installation marker
  whose runtime generation had previously been removed. A new CPU installation
  was prepared and verified. Test preflight now rejects missing runtimes, pin
  mismatches and missing authored fixture files before the applicable checks.
- **Harness timing:** initial expanded-control checks accessed newly navigated
  WPF pages before layout completed. Updating layout after button dispatch fixed
  that driver issue. Failed evidence is preserved.
- **Clipboard contention:** the clean combined run could not read the existing
  clipboard (`0x800401D0`) before the copy scenario in `app-e2e-c1929392` and
  `app-e2e-c157eaa2`. The driver now retries only that specific clipboard-access
  error for at most three seconds when preserving, reading or restoring data.
  Scout actions and assertions are not retried. A subsequent focused control run
  passed all 22 scenarios with 117 inventory entries (`app-e2e-16448bfe`).
- **User interruption:** Escape interrupted an earlier session. Its partial
  scheduler output is retained and excluded from product pass/fail conclusions.

This suite covers the feature surfaces and main workflows above. It does not
prove every possible state, corrupted input, Windows build or hardware combination.
Lock/sleep/radio changes and personal-data deletion were not applied to the PC;
their selection/dispatch boundaries are covered by contracts. Tray Quit presence
is checked, and native keyboard exit was exercised separately.

## Evening PDF and concurrency follow-up

The hidden baseline passed 90 renders. The next longer run, `release-20261019/
pdf-final`, failed iterations 0 and 29 while opening `ready.json`: Windows reported
that another process held the receipt. Publication was atomic, but the reader
rejected transient sharing contention immediately. `SemanticExtractor.ReadJsonAsync`
now retries only sharing/lock violations for at most two seconds, with cancellation
between attempts. File sharing permissions, byte limits, depth/schema/hash checks
and rejection of malformed content remain intact. The same helper reads prepared
extraction/playback receipts. Four new native tests cover release of an actual
exclusive lock, cancellation, a persistent lock, and invalid/oversized JSON.

PDF navigation also advanced its selected page before rendering succeeded. It now
commits the page after successful rendering, so failure retains the last displayed
page and the next click retries the intended page. An injected failure through
the actual WPF Previous/Next handlers fails with the old order and passes with the
fix (`pdf-recovery-before` versus `pdf-recovery-hidden-v3`). Worker startup failures
also include the native exit code for future diagnosis.

The fixed package passed 120 real renders, distinct/repeatable page raster hashes,
cancellation, malformed input, source preservation, session cleanup and the hidden
WPF failure/retry check (`release-20261019/pdf-sharing-fixed`). Its published
`Scout.dll` SHA-256 is
`abdabfa16a81e3fc1108fcce68d5de65f6f3a61ad4c5098a68878eeb0f932da8`.
One early harness attempt inadvertently invoked normal Scout startup in a private
profile and was terminated. It may have enumerated default folders into that
ignored private index; the normal Scout profile was unchanged. A subclass resource
loading attempt also failed. The final harness uses a plain WPF Application,
loads only the tracked resource definitions and asserts that its sole window is
never visible. It does not construct Scout's application/startup path.

TesterArmy run `00c3f57e-a70d-446a-b0b1-3ec0e66c8fc4` passes all 355 native checks,
the hidden PDF checks and the concurrency workload. Run
`3029b6a5-f445-43f2-a713-4dd9430e8d7c` passes the final PDF/concurrency drivers,
including actual Laya reset and abrupt-owner-death cleanup. The watchdog stops
its server while the parent test job is still open; parent-job closure is not
used as proof of watchdog behavior. All reports are under the E2E `runs/` directory.
