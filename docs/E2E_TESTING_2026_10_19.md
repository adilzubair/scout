# Windows end-to-end verification, 2026-10-19

Branch: `feature/multimodal-semantic-search`, starting commit `da40fa8`.
This is development-machine verification of the real Windows application.
The current package is not approved for general release. Physical 16 GB testing
is scheduled after release at the user's direction; minimum-hardware claims
remain provisional. That scheduling change does not waive the other gates.

## Runner and references

The repeatable suite is [tests/Scout.E2E](../tests/Scout.E2E/README.md), using
[TesterArmy e2e](https://github.com/tester-army/e2e) 0.21.2, inspected at
`7b6ac5327eb6f98fb51f7e22184fdd5274905e75`. Its built-in engines target browsers
and mobile apps. Scout uses an engine-free Windows target with custom steps that
invoke the real WPF integration driver, native regressions and local Python/model
checks. Browser mocks are not used as evidence of native application behavior.
Telemetry, remote AI, retries and runner caching are disabled. Reports and failed
evidence are retained under ignored `artifacts/diagnostics/e2e/`.
`npm audit` reported zero known vulnerabilities for the pinned runner dependency
tree on this date.

[DigUp](https://github.com/ARahim3/DigUp) was inspected at
`7db9537712995d14e50e0e44baa00f721b98f1c6`, including its Windows
`0.7.0-beta.2` update manifest and package checklist. Its isolated-profile launch,
authored-file indexing, query, helper-runtime, notices and clean-exit checks were
useful reference points. No DigUp application code was copied. Its release does
not establish compatibility or release readiness for Scout.

## Installation defect fixed

The shipping Laya setup failed on a fresh private environment because PyPI no
longer provides `laya==0.3.7`. The original upstream v0.3.7 tag resolves to commit
`010bacef009c855ccba814b51f7c8e1d38ab5e3f`. Requirements now use that immutable
official source archive, pinned with SHA-256
`db7efbfe4a472b8af59a8ecae2ea6b13199679f79f77bc911f100c13b527dda7`.
All nine runtime Python files match the previously tested installation after
normalizing line endings; neither the Laya runtime version nor model revision
was upgraded. See [third-party provenance](THIRD_PARTY.md).

The actual shipping setup script then installed its private interpreter and
dependencies and downloaded the English checkpoint from the unchanged pinned
revision. A repeat run was idempotent. The resulting private environment passed
all 13 adapter tests and authenticated HTTP checks using its own newly downloaded
model, rather than the development model cache. Evidence:
`laya-fresh-setup.log` (original failure), `laya-setup-retry.log` (successful fresh
download), `laya-install.log`, and run
`180e9594-08b6-471d-9cd6-d0256ffba503/report.json`.
The upstream checkpoint's existing temperature-calibration warning remains;
these tests do not approve its confidence calibration.

## Retained failures and limits

- **Packaging/security block:** `scripts/test-package.ps1:39` was rejected by
  local antivirus with “This script contains malicious content and has been
  blocked by your antivirus software.” `packaging.log` and the initial failed
  runner report are retained. Antivirus was not disabled and the script was not
  rewritten or rerouted to evade the block. Security review and a normal successful
  packaging run are required before publishing release artifacts.
- **Intermittent PDF failure:** `app-e2e-04c15bf8` failed page navigation once.
  A later complete run and three focused repetitions passed. Additional expected/
  actual page/status diagnostics and repeat checks were added; the root cause has
  not been established. A passing retry is not a claimed product fix.
- **Stale test installation:** the first run referenced an installation marker
  whose runtime generation had previously been removed. A new CPU installation
  was prepared and verified. Test preflight now rejects missing runtimes, pin
  mismatches and missing authored fixture files before the applicable checks.
- **Harness timing:** initial expanded-control checks accessed newly navigated
  WPF pages before layout completed. Updating layout after button dispatch fixed
  that driver issue. Failed evidence is preserved.
- **Clipboard contention:** the clean combined run could not read the existing
  clipboard (`0x800401D0`) before the copy scenario in `app-e2e-c1929392` and
  `app-e2e-c157eaa2`. The driver now retries only that specific clipboard-access
  error for at most three seconds when preserving, reading or restoring data.
  Scout actions and assertions are not retried. A subsequent focused control run
  passed all 22 scenarios with 117 inventory entries (`app-e2e-16448bfe`).
- **User interruption:** Escape interrupted an earlier session. Its partial
  scheduler output is retained and excluded from product pass/fail conclusions.

This suite covers the feature surfaces and main workflows above. It does not
prove every possible state, corrupted input, Windows build or hardware combination.
Lock/sleep/radio changes and personal-data deletion were not applied to the PC;
their selection/dispatch boundaries are covered by contracts. Tray Quit presence
is checked, and native keyboard exit was exercised separately.

   failure, and test a newly built, complete distribution through its normal checks.
2. Rehearse clean standard-account installation, first launch, interrupted setup,
   upgrade, removal and leftover-process/data behavior for the final installer and
   portable package. The post-install E2E directory contains private dependencies
   and model weights and must not be distributed as the base release ZIP.
3. Complete the independent seven-family 400-task quality holdout, supported
   negatives/abstention calibration and natural audiovisual quality evaluation.
   Authored smoke fixtures and compatibility tests do not discharge this work.
4. Complete broader ordinary-search, Laya enabled/disabled and concurrent workload
   timing/resource measurements, final dependency/license/distribution review and
   artifact checksums. The existing release plan remains the source for those gates.
5. Reconcile the feature branch with current remote main, review its complete
   outgoing history, obtain green required CI/review checks and then merge/push
   the reviewed state. Testing here has not merged, pushed or published anything.

Physical 16 GB startup, memory, indexing and search measurements are post-release
follow-up, as requested. Do not describe that configuration as validated yet.
